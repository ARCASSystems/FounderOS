# v1.48.1 - the voice layer works on day one, and says exactly what leaves your machine

An end-to-end review ran over the optional voice layer, checking every claim against the code and against the live APIs rather than against the docs. Four things failed. Two were dead ends a user would hit on their first attempt, one was a routing collision on the word "voice", and one was a privacy sentence that was more flattering than true.

## What changed

- **The paid mouth was broken, and is now fixed.** `add-mouth`'s ElevenLabs engine asked for `eleven_monolingual_v1`. That model was retired: the API now answers `400 unsupported_model, deprecated and no longer available`. Anyone who paid for ElevenLabs and wired the premium mouth got a failed request with no useful reason. The default is now `eleven_multilingual_v2` (verified against a live key), it is overridable as `"model"` in `voice/mouth-config.json`, and the failure message now tells you which of the two real causes you hit: a retired model id (400) or a voice that needs a paid plan (402).
- **A copy-paste line in the realtime installer named a model that does not exist.** The usage block in `setup_realtime.py` showed `--model gemini-live-2.5-flash-native-audio`. That name is not in the model list any key returns. The wired default was always correct; the example was not, and the example is what gets copied. It now names the real one.
- **"Set up my voice" stopped being ambiguous.** Voice means two different things here: `voice-interview` captures how you WRITE (the profile every writing skill reads), and `add-voice` installs SPEAKING and LISTENING. Their trigger phrases overlapped almost exactly, so the same sentence could land in either. Both now claim their own half in their description and name the other, `add-voice` asks a one-line check before installing a runtime nobody asked for, and the voice-interview opening says plainly that it is not the talking-out-loud one.
- **The realtime privacy claim now matches the code.** The docs said your files and the answers read from them stay local, and only the conversation leaves. The first half is true. The second is not: when the realtime front asks your local brain a question, the answer is sent back into the cloud session so the front can speak it. The honest line, now stated in the skill, the disclaimer, and the architecture note, is that the FILE stays home and the SENTENCE does not. It carries the matching lesson from the private build that has run this loop the longest: a system prompt asking a model to be discreet is a request, not a guarantee, and this layer ships no outbound filter.
- **Model ids are now treated as claims, not facts.** The tier docs tell you to check `python voice/live_server.py --models` against your own key rather than trusting a printed name, because a retired name fails at the first turn. Both model defaults carry the date they were verified.

## Why it matters to you

**If you use voice at all:** nothing in your install changes behaviour except the two dead names. Take the patch and the paid mouth works; skip it and it does not.

**If you were thinking about realtime (Tier 1):** read the privacy paragraph before your next session. It is shorter and less comfortable than the one it replaces, and it is the accurate one. If a fact is too sensitive to hand a cloud model, do not ask for it out loud - ask it in text, or run Tier 0-local, where nothing leaves at all.

**If you never wanted voice:** nothing here reaches you. The OS is complete as text; voice stays opt-in and is never the headline.

## Integration protocol

1. **Take the system-layer files.** All engine; nothing writes into your data folders.
2. **If you use the ElevenLabs mouth:** re-run `python skills/add-mouth/setup.py --engine elevenlabs`, or just take the new `say.py`. Confirm with one short line spoken.
3. **If you run realtime:** run `python voice/live_server.py --models` once and confirm your configured model is in the list your key returns. If it is not, pick one that is.

## No Claude Code? The by-hand path

**Open whatever you use for text-to-speech and check the model id against the vendor's live model list today.** A model id in a doc has a shelf life, and the failure it produces is a flat error with no hint. The fix is one line; finding it without the hint is an evening.
