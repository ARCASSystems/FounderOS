# v1.45.0 - git is plumbing, never the interface

The OS has run without git since the ZIP install landed: session snapshots cover undo, updates work over plain download, and the caveman verbs wrap git for the installs that have it. What had not caught up was the text. A rules file installed a push cadence onto machines with no git, the tour said "your repo is your memory", the session-end protocol opened with a commit instruction, and one doc claimed updates need `git pull`. This pack is the words catching up with the machine.

## What changed

- **`rules/commit-naming.md` scopes itself.** It now says up front that it lives in the version-history layer and that on an install without history nothing in it fires. The rejected-push line explains recovery in plain words - the OS brings the remote changes down and re-applies yours - instead of rebase jargon.
- **The global config template drops its git advice.** "Verify with git status and a file read" became "verify with a file read", and the history rules (main is the working branch, never force push) are named as dormant until history is on.
- **Session end tells the truth about memory.** The old first step said commit everything to git. The new one: files persist the moment they are written, and the next session reads them with nothing else needed. With history on, the session is also recorded as one saved version. The tour's "your repo is your memory" became "your files are your memory."
- **Updates need no git command on any path.** The install doc's claim that Path B updates are manual via `git pull` is gone; "update Founder OS" works the same everywhere. A new section in `docs/install.md` names the three layers in one place: folders that are yours and never written by an update, folders that are the OS's and replaced freely, and the three files in between that updates propose as diffs you accept or decline per file.
- **The version verbs speak your language.** The skills catalogue's save, history, restore, and backup entries describe saved versions and timelines instead of `git status`, `git log`, and reset flags - with one honest line kept: git is the plumbing underneath, run for you.

## Why it matters to you

**If you installed from the ZIP and never touched git:** this pack removes every place the OS's own text asked you to think in git. Nothing about your files changes; what changes is that no rule, tour line, or doc will send you to a terminal you never signed up for.

**If your install uses git:** everything you rely on still works exactly as before - the guard, the saves, the push cadence when you sync between machines. The only difference is that those rules now say who they are for.

**You can skip this pack** if you have heavily edited `rules/commit-naming.md` or `rules/operating-rules.md` and prefer your own wording. The changes are wording, not machinery.

## Integration protocol

1. **The docs and skills update automatically.** They are system layer.
2. **`rules/commit-naming.md` and `rules/operating-rules.md` are yours**, so the update shows each change as a diff. The two worth taking: the scope line at the top of commit-naming (it stops the file from ever telling a no-git install to push), and the new session-end step 1 in operating-rules (files persist at write time - the line your assistant reads at every session close).
3. **If you declined the v1.43 push-cadence section back then,** nothing new asks you to reconsider. The section only gained a plainer recovery line.
4. **Nothing to run, nothing to test.** This pack changes what the OS says, not what it does.

## No Claude Code? The by-hand path

**Make one edit: in your `rules/operating-rules.md`, replace the Session End Protocol's first step with:**

> Nothing to save by hand: files persist the moment they are written, and the next session reads them as they are. With version history on, also record the session as one saved version.

That single line is the heart of the pack - it is the sentence that makes cross-session memory a property of your files instead of a git habit.
