# v1.45.1 - honest boundaries: uninstall cannot eat your data, and the charter says what it is

An independent end-to-end review ran over the pushed v1.45.0 - the fourth pass on this range - and every confirmed finding shipped as this patch. Three were blockers: the standalone uninstaller could delete operator data, a fresh extract never installed the natively discoverable skills, and the charter language claimed an enforcement Claude Code does not provide today.

## What changed

- **Uninstall now deletes only what it can name.** Both uninstallers (the command and `uninstall.sh`) replaced their preserve-and-wipe strategy with a remove-list of named system paths. A folder the list has never heard of - your employee registry, your quarantine record, your rules, your brand config, a company folder setup created - survives by construction. `rules/` left the default removal list (update classifies it as yours), and purge mode now removes everything it claims to, asking per folder about root directories it cannot name.
- **The charter language matches Claude Code's documented behavior.** A skill's `allowed-tools` is pre-approval, not a wall; restrictive enforcement is an open upstream request. Every surface now says the true thing: the grant is a written contract in two places kept identical, the charter audit names drift in both directions, and anything outside a grant routes through your own permission prompts.
- **The charter audit grew the teeth the claim needs.** It now catches the reverse drift (a charter tool no chain skill declares), parses every frontmatter shape (inline, multiline, space-separated), flags empty declarations and interpreter-wide wildcards like `Bash(python *)`, and compares case-sensitively.
- **A fresh install can actually see its skills.** Setup now runs `python scripts/skills_sync.py --apply` and proves it clean with `--check` before generating the capability page. Before this, the manifest's discoverable skills never reached `.claude/skills/` on a new extract.
- **Loop and guard repairs.** Future-dated verdicts stop triggering reviews; impossible dates like `2026-99-99` fail the entry guard; a completed review with nothing to change still stamps `last_review` so REVIEW DUE clears; the weekly review refreshes a stale brain snapshot at 3 days; the morning loop closes asks in `brain/needs-input.md` too; a ZIP install on a git-equipped machine asks before turning version history on; wizard timestamps use Python, not a Unix-only `date`.

## Why it matters to you

**If you might ever uninstall or purge:** this is the difference between losing the registry, rules, and brand config you personalized, and losing nothing you did not explicitly name. Take the patch before you ever run an uninstall.

**If you run the five roles:** the boundary is now described exactly as strong as it is - a written, audited contract with your permission prompts as the backstop - and the audit that guards it catches the drift classes it used to miss. Run `python scripts/employee_verdict.py charters` after updating.

**If your install predates this patch:** run `python scripts/skills_sync.py --apply` once, then `--check`. If check was failing before, your OS just gained native discovery of its own core skills.

## Integration protocol

1. **Take the system-layer files.** Everything above is engine; nothing writes into your data folders.
2. **Run once:** `python scripts/skills_sync.py --apply` then `--check`. Clean check means your core skills are natively discoverable.
3. **Run once:** `python scripts/employee_verdict.py charters`. Findings name the exact file and field to align; clean means your registry and your skills agree.
4. **If you kept the old `uninstall.sh` anywhere, replace it.** The old one deletes what it cannot name.

## No Claude Code? The by-hand path

**Open `uninstall.sh` (or whatever you use to remove the OS) and make sure it deletes a named list of system folders rather than "everything except a list of yours."** That single inversion is the whole safety property: a keep-list destroys whatever it forgot, a remove-list spares whatever it never knew.
