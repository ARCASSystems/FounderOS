# v1.43.0 - the scripts pack

Four standard-library scripts and two new commands. No new dependency, no install step, no server, and no API key.

## What changed

**The provisional-fact ledger** (`scripts/unconfirmed_facts.py`). Something said once in a call and never spelled out - a company name, a surname, a number you never saw written down - now waits in a ledger instead of sitting in your notes reading exactly like a fact. Confirming it records the value and names the file it belongs in. Writing it into that file stays your step, deliberately. The ledger refuses to hold an email, a phone number, or an amount.

**The verdict loop** (`scripts/employee_verdict.py`). If you run recurring jobs, one line after a run you actually saw - ok, needs-work, or failed, plus why - is the whole input to a review that proposes changes to the job. Review is due on two triggers only, and with no verdicts nothing is ever due. Also `charters`, which audits whether a job's actual permissions match what its description claims. That check exists because the failure is common and invisible: a job whose prompt says "never sends anything" holding a grant that covers every script on the machine.

**Skill reachability** (`scripts/skills_sync.py`). A skill only runs if something can find it. `/founder-os:verify` now checks that every skill is reachable from at least one surface, and names any that are reachable from nothing. `skills/discoverable.yaml` promotes the handful worth reaching the moment you describe a situation rather than after the model reads a registry.

**Capture sweep** (`/founder-os:capture-sweep`). The OS notices what was recorded and proposes where each item goes, sorted into a conversation with someone, training media, internal talk, or personal. Personal is skipped and counted, never filed.

**`scripts/flat_yaml.py`** is the small reader underneath the registry files. It exists so none of this needs `pip install`.

## Why it matters to you

**If most of your meetings are recorded once, on one device:** the ledger is the reason to take this pack. That is the normal case and it has a failure mode that does not look like one. A single recording leaves nearly every proper noun unconfirmed, the notes read fluently and confidently, and two weeks later an unconfirmed name is in a document and nobody can say where it came from. The fix is never a better transcript, because the information was never in the audio. It is a second source, or you confirming it.

**If you have written a lot of skills:** run the reachability check once. It is a two-second answer to a question worth asking, and a skill nothing points at looks perfectly healthy from the outside while never running.

**If you do not run recurring jobs yet:** skip the verdict loop entirely. It ships with an empty registry and it does nothing until you add a row. Nothing is wrong with your install if it stays empty forever.

**You can skip this whole pack** if your capture is already double-sourced and you write few skills. It adds no behavior on its own: every script here has to be called before it does anything.

## Integration protocol

1. **Take the four scripts.** They are new files, so nothing of yours is at risk. None of them runs unless something calls it.
2. **`skills/verify/SKILL.md` gained Check 9.** If you have edited that file, read the proposed diff. The change is one new check section and a count going from eight to nine.
3. **Run the reachability check right now.** It takes two seconds and tells you something real:
   ```
   python scripts/skills_sync.py --reachability
   ```
   If it names skills reachable from nothing, fix any one way: add a row to `skills/index.md`, add a slash command, or promote it in `skills/discoverable.yaml`.
4. **If `modules.unconfirmed_facts` is `no` in your `os-config.yaml`,** decide now whether to turn it on. Turn it on if your meetings are usually recorded once and you work with people whose names you have only heard. Leave it off if your capture is already double-sourced. There is no partial state: the ledger only helps if things actually get logged into it.
5. **If `modules.employees` is `no`,** skip `employee_verdict.py` and its command. The script is on disk and inert. Come back when a job has recurred three times and you have corrected it twice.
6. **Optional, and only if you want a few skills reachable natively:**
   ```
   python scripts/skills_sync.py --apply
   ```
   That copies the skills named in `skills/discoverable.yaml` into `.claude/skills/`, which is where Claude Code discovers skills on its own. Keep that list short. Promoting all of them makes every skill compete for attention at once, which is a different way to be undiscoverable.

## No Claude Code? The by-hand path

**Copy one file: `scripts/unconfirmed_facts.py`.**

It is standard-library Python and it runs anywhere Python 3 runs, with no OS around it and no assistant involved:

```
python unconfirmed_facts.py add --fact "the company may be called Acme" \
    --context "said once on the call, never spelled out" --source recorder
python unconfirmed_facts.py list --status open
python unconfirmed_facts.py confirm --id uf-2026-07-25-001 --value "Acme Holdings" --note "confirmed by email"
```

That is the whole loop, and it works as a standalone tool.

If you would rather not run anything at all, the idea is portable and worth taking on its own: keep one plain list of names and claims you have heard exactly once, and never let anything move off that list into a document until a second source or a person confirms it. The script only makes the list harder to forget.
