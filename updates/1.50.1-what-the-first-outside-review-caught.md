# v1.50.1 - what the first outside review caught

v1.49 and v1.50 shipped in one night. Before building anything new on top of them, the whole range went through an independent review with one instruction: run the scripts, do not trust the prose. It came back with 18 findings. Every one was reproduced or refuted against live behaviour; the reproduced ones are fixed here. This is the patch, and the review habit is the point: the same pass caught v1.48.1's broken voice before users did.

## What changed

- **A seat id can no longer write outside your agents folder.** A registry row with an id like `../../README` used to make `agents_sync.py` write a file OUTSIDE `.claude/agents/` - over a repository file if the name lined up - and report success. Ids are now validated (lowercase letters, digits, inner hyphens), duplicates are rejected, and a mechanical containment check refuses any write or delete outside the folder.

- **The secret scanner never prints what it hides.** A line carrying a secret plus a second violation (an em dash, a private name, an attribution trailer) was echoed raw by the second finding. Now the secret check runs first, and a secret-carrying line is hidden from every finding on it.

- **Your edits to a generated agent file survive.** The generator's marker line now records a digest of what it generated. If you edited a generated file, it is reported `[modified]`, the check fails loudly, and nothing overwrites or deletes your edit - on update AND on retirement. A hand-written file sitting where a rostered seat's file should be now fails the check too, instead of hiding under "agent files match the registry".

- **A correction has to be aimed at the OS to be captured.** Quoting a client's feedback, telling a story about feedback you gave a human, or a long brief that happens to contain "I already told you" no longer registers as a correction of the OS. Short direct replies ("too long", "just pick one") still capture - that is the feature working.

- **A fresh install can talk to its starter team.** Setup copied the org chart and the generator but never ran it, so the five starter roles could not be dispatched by name until your first hire. Setup now generates and verifies the agent files, and stops loudly if that fails.

- **The unwatched-run count stops guessing.** Every run now carries a `run_id`. A verdict recorded with `--ref run:<id>` names the run it grades; the summary counts as unwatched exactly the runs no verdict names, and reports verdicts tied to no run separately. The seat reviewer now reads the run log as first-class evidence and only refuses a review when verdicts, filed items, and runs are ALL empty.

- **The documented failure path records the failure.** The run-record instructions in generated agent files and five skills told a failing run to record without the reason the script requires - following them on a failure produced an error and no record. All seven surfaces now show the working form, including what the run read and produced.

## Why it matters to you

**If you use the team features:** the first three fixes are the ones protecting your files - a malformed org chart cannot reach outside its folder, and your own edits cannot be silently destroyed by a sync.

**If you correct the OS mid-work:** the capture that builds `core/working-preferences.md` is now much harder to trip by accident. A wrong row that slipped in through quoted text can be deleted by opening the file - it is yours.

**If you never touched any of this:** take the update anyway. The id validation and the secret-scanner fix are the kind you want in place before you need them.

## Integration protocol

1. **Copy the four changed scripts** from `templates/scripts/` into your `scripts/`, byte-for-byte: `agents_sync.py`, `check-private-names.py`, `user-prompt-capture.py`, `agent_runs.py`.
2. **Regenerate your agent files:** `python scripts/agents_sync.py apply`, then `check`. If you ever edited a generated agent file by hand, `check` will now name it `[modified]` instead of clobbering it - fold your edit into the registry row, or keep the file and accept the drift knowingly.
3. **Take the skill-body changes** for hire, employee-review, and the four closing acts if you have not edited those skills; otherwise merge the changed sections by hand.
4. Nothing here touches your data folders.

## No Claude Code? The by-hand path

**Three habits this patch encodes.** First: anything that turns a name into a file path gets validated before it writes - a list of allowed characters and a check that the result stayed inside the folder you meant. Second: a tool that hides sensitive values must hide them in EVERY message it prints, not just the message about the secret. Third: when you write instructions for a process, test the failure path by following the instructions during a real failure - the happy path never finds the error that strands a failing run with no record.
