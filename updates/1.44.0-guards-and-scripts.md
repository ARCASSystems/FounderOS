# v1.44.0 - two commit guards, and seven scripts that never installed

The mechanical half of the release. Two new checks on the commit hook, one generated page, and a packaging bug that had been quietly hollowing out several shipped features.

## What changed

**Seven scripts were in the repo but never reached an install.** The setup wizard copies a named list of helpers into your `scripts/` folder, and seven were missing from it: `employee_verdict.py`, `flat_yaml.py`, `unconfirmed_facts.py`, `deliverable_gate.py`, `selfdoc_check.py`, `skills_sync.py` and `scrape.py`. Each backs something the OS tells you to use. The v1.43 update pack told founders to run `python scripts/deliverable_gate.py` on a real file, and on a real install that command did not exist. The morning loop calls `unconfirmed_facts.py` by name. `entry-conventions.md` names `selfdoc_check.py`. All seven now ship, and the copy step reads the folder rather than a list that can fall behind it.

**A line-ending guard on the commit hook.** One stray carriage return inside a file's content turns off git's line-ending normalization, so the whole file lands with the other style and every line reads as changed. The real diff disappears into the churn, and the next machine that appends to that file writes a mixed one. This matters more for a public OS than a private one, because cross-platform is the normal case here and the corruption is invisible until something breaks. Two checks now: a lone carriage return inside content, and an ending style that flips against what is already committed. `raw/` is exempt, because a source document is written once and keeps whatever bytes it arrived with. Override for a deliberate normalization commit: `ALLOW_EOL=1`.

**An entry-form guard on the same hook.** A decay field spelled `Decay After:` is never seen by the thing that reads it. The entry looks correct, never surfaces for review, and nothing anywhere tells you. The hook now checks added lines in your brain channels against the canonical form in `rules/entry-conventions.md`: field names exact, dates and durations readable, entry ids on the right channel with a three-digit counter. It reads added lines only, so nothing old is ever dragged into a form that postdates it, and it ignores unfilled template slots. Override: `ALLOW_ENTRY=1`.

**A generated page answering "what can this actually do".** `docs/what-this-can-do.md`, built from the skills on your disk, grouped by what you would reach for them for. It is never hand-maintained, because a maintained list is wrong the first week somebody forgets, and a wrong capability list is worse than none: it teaches you the OS cannot do something it can. The commit hook refuses a skill change that leaves the page stale, and names the one command to rebuild it.

**The canonical entry form is now written down.** `rules/entry-conventions.md` described what to write but never specified the exact shape, which is why near-misses were possible. It now carries the field list, the value shapes, and the id format, plus what the new gate does and the three things it deliberately does not do.

## Why it matters to you

**If you have been running the OS for months:** the seven scripts are the one to act on. Check whether they are in your `scripts/` folder. If they are not, several things you have been told to run have been quietly unavailable, including the ship gate.

**If you write in your brain files by hand:** the entry gate will catch a typo that used to cost you a review you never knew you missed. It only fires on lines you add.

**If you work across a Mac and a Windows machine, or run anything on a server:** the line-ending guard is the one that saves you a confusing afternoon.

**You can skip the guards** by not installing the hook. They are a commit-time convenience, and nothing about your daily use depends on them.

## Integration protocol

1. **Take all seven scripts.** There is nothing personalized in any of them and no merge to think about. If you decline one, the feature it backs stays unavailable.
2. **Generate the capability page once:**
   ```
   python scripts/skills_sync.py --capabilities
   ```
   Read it. It is the fastest way to find out what you have been ignoring.
3. **Re-install the commit hook** if you use git version history, so the two new gates are live:
   ```
   bash scripts/install-git-hooks.sh
   ```
4. **Prove the line-ending guard once, on a throwaway commit.** A guard you have never seen fire is a guard you do not know is installed.
5. **Do not backfill your old entries.** The entry gate reads added lines only, on purpose. Old entries adopt the form the next time you touch them, exactly as `entry-conventions.md` has always said.
6. **Take `templates/rules/entry-conventions.md`** if you have not edited your copy. If you have, read the diff: it adds one section and rewrites one bullet, and leaves the rest alone.

## No Claude Code? The by-hand path

**Copy the seven scripts into your `scripts/` folder.** Six of them are standard-library Python, need no configuration, and resolve their own paths from where they sit. That is the whole install for those six.

The seventh, `scrape.py`, is the one exception in the whole OS and it is worth knowing about rather than discovering: it needs `pip install httpx selectolax tenacity` before it does anything, and its `--render` mode additionally needs playwright. Copy it anyway. Without the packages it exits immediately with the exact command and points you at the built-in fetch as the fallback, so the skill behind it degrades instead of breaking. Nothing else in this release, and nothing in your daily loop, asks you to install a package.

Then run one command and read the output:

```
python scripts/skills_sync.py --capabilities
```

If you want a second thing with no tooling at all, open `rules/entry-conventions.md` at the section called "The canonical form" and keep it next to you the first few times you write a flag by hand. The field names are case-sensitive and that is the entire trap.
