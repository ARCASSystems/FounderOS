# v1.54.0 - it can prove its own install

Five defects shipped in v1.53.0 through green CI, and every one of them lived in an install rather than the repo. Nothing checked an install. The health check could not have caught them either, and the reason is uncomfortable: its own instructions said "enumerate dynamically, do not hardcode a list", and a check that derives its expectations from whatever is on disk cannot notice that something is missing from disk. A deleted file was invisible to it at any model quality.

This release gives the OS a way to prove its install is complete, makes the backup answer tell the truth about what version history actually holds, lets an interrupted setup pick itself back up, and closes three smaller hardenings from the same outside review.

## What changed

- **"Verify the OS" now proves, not estimates.** A new script derives the list of everything an install must hold from what setup actually copies - never a hand-maintained list, which is how "thirty-two helpers" once went stale - and compares your folder against it: every shipped script present and undamaged, the hook engine in place, the six session hooks wired, the version marker readable. Delete one file from a working install and the check names it. The same proof runs against the public repo before every release ships, so the product can no longer ship a release that fails its own checkup.

- **The backup line now tells two truths instead of one blur.** "Backed up" used to mean "version history has heard of this file", which is true of a file that was staged once and never committed - a file whose only copy is the laptop. Now the answer separates saved from copied: a folder that was never saved says so, a folder with unsaved changes from today says "an older version is saved - today's changes exist only here", a folder saved only on this computer says that plainly, and "backed up" appears only when a second copy provably exists away from the machine.

- **Finding your work got sharper.** Ask "where is the vendor list" and folders whose file names match come back first, honestly labelled (names are not content, so a miss never means the work is gone). Version history is now detected properly even when your OS folder lives inside a bigger folder that has its own. Projects you named docs or templates no longer vanish from the answer on a plugin install. Files sitting at the folder root are counted instead of dropped. And a gigantic folder answers partially and says so, instead of hanging.

- **An interrupted setup resumes instead of playing dead.** Setup takes 15 to 20 minutes and laptops close. Setup now leaves a small progress note after every phase and a completion note only after its final health check passes. Double-click the start file after an interruption and it says where you stopped and carries on - it does not restart the interview, does not re-ask what you answered, and does not silently open as though nothing happened. Installs finished before this release open exactly as they always did.

- **Opening a found folder is now mechanical, not improvised.** When the OS offers to open a folder it found, a small helper does it: the folder name travels as data, never as part of a typed command, and anything outside your OS folder is refused. A folder name with odd characters in it can no longer become something a shell interprets.

- **A note's topic can no longer read as an order.** Knowledge notes routed to your digital employees render their topic in quotes on the seat's instruction sheet, so a topic phrased like an instruction reads as a label being reported, not a command being given.

## Why it matters to you

**If you have ever wondered "is my install actually complete":** say "verify the OS". For the first time the answer is a proof, not an impression.

**If you keep real work in your OS folder:** run "where is my work" once after this update. The backup line is stricter now, and a folder it previously called backed up may honestly be saved-on-this-computer-only. That is not a regression - it is the first true answer.

**If setup ever stalled halfway and you shrugged and moved on:** double-click the start file. It knows where you stopped.

**If none of this touches you:** the changes are all in the OS's own machinery. Your files, your notes, and your day-to-day flow are unchanged.

## Integration protocol

1. **Copy the four scripts:** `templates/scripts/verify.py`, `templates/scripts/open_folder.py`, `templates/scripts/where.py`, and `templates/scripts/agents_sync.py` each go over their `scripts/` twin. Straight copies, no personalization.
2. **Run the new proof once:** `python scripts/verify.py`. Expect all green; anything it names is real.
3. **If you run the employees module**, run `python scripts/agents_sync.py apply` once - tagged knowledge notes re-render with quoted topics, and your own edits to any seat file are detected and left alone as always.
4. The skill, command, and launcher files in the table arrive with the update itself. The setup markers only matter for future setups and re-runs; a finished install needs nothing.

## No Claude Code? The by-hand path

Copy `templates/scripts/verify.py` over `scripts/verify.py` and run `python scripts/verify.py` in your OS folder. That one command is most of this release: it tells you, in five lines, whether your install is whole - every shipped script present and undamaged, the hooks wired, the version marker readable. If it names a missing file, re-download the ZIP and copy that one file back in.
