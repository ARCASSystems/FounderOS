# v1.55.2 - the rest of the front door

1.55.1 fixed the front-door claims a first audit found. After it shipped, a full read of every public page, done the way a stranger would read them, found more of the same kind. This release fixes those. It adds no feature.

## What changed

- **No page promises that nothing leaves without you.** Four places still said it: the first-day guide, the day-in-the-OS walkthrough, the first-30-days template, and the local-first line in `CLAUDE.md`. Each now says what is true.

  The skills that write to people draft and stop. The few that send or publish, like a backup push or a GitHub action, act only when you ask. Until a hard send gate ships, that is a written rule that nothing enforces yet. What a session reads goes to Anthropic under your Claude plan, and ARCAS receives nothing. The skill pages that made the same promise, the voice pages and the pack front doors among them, now say this too.

  Three narrower promises of the same kind are fixed as well. The LinkedIn pages said your names never leave the machine: the raw export stays, but the names in the digest reach Anthropic when the session reads it. The version-history steps said your git name and email stay on this machine: they are saved on every version, so they go wherever you later back up. The private-names notes said the names in your patterns file never leave: they never enter your history or any push, which is what the file protects.

- **Template examples changed.** `templates/rules/entry-conventions.md` now shows a superseded decision about a review day, and the needs-input and log templates use a generic offer name.

- **The security page names one more surface.** Connectors and plugins you enabled on your claude.ai account load in Claude Code sessions signed in with that account. `rules/security-baseline.md` now has that row, with how to turn them off.

- **The cloud pages agree with each other.** Claude Code on the web runs scripts and a repo's own hooks, on a GitHub copy in Anthropic's cloud, never on your folder. The README's phone line now names Remote Control, which drives a session on your own computer and keeps your files there, and the surface table gives the web its own row instead of sharing one with chat.

- **The Mac first run follows Apple's current steps.** The docs said to right-click the start file and choose Open. Apple's help page now says to try opening it once, then open System Settings, then Privacy & Security, click Open Anyway, and confirm with Open. The README, the install guide and the start file say that now, and say we haven't yet run it on a real Mac.

- **Install-path instructions that stranded people.** The first-day guide and the commands reference told ZIP users to type `/founder-os:setup`, which only works on a plugin install. The README promised that re-running the curl installer updates an install. It stops once the OS has saved your work, so the pages now point at "update Founder OS".

- **Smaller corrections.** The Agent Teams section is now marked optional and experimental, with no model requirement and Anthropic's note on token use. The claude-mem note says Apache-2.0, which its GitHub page shows.

  The tools table names the `pitch-deck` skill. The README counts four install paths plus Cowork, lists identity among the six operating files, and drops a price range it could not source. Path labels, a stale skill count, a stale code reference and two references to a README table that no longer exists are fixed.

## Why it matters to you

If you read the first-day guide or the first-30-days page and took "nothing leaves your machine without you" as a technical promise, it wasn't one. The skills are written to draft and stop. Until the hard send gate ships, read a draft before you ask for it to go out.

If you installed from the ZIP and the first-day guide told you to type `/founder-os:setup`, type `/setup` instead.

If you're on a Mac and the start file wouldn't open, use System Settings, then Privacy & Security, then Open Anyway, and confirm with Open.

If you enabled Gmail, Calendar or Drive on your claude.ai account, those connectors are live in your Claude Code sessions too, and the security page now lists them.

If you ran the LinkedIn scan or audit, the raw export stayed on your machine, but the names in the digest or `audit.json` went to Anthropic with your session, as everything a session reads does.

If none of this touches you, nothing in your own files changes.

## What the release gate found before this shipped

This release is itself the output of a gate. A full read of the shipped 1.55.1 tree by a context that built none of it returned ten serious and sixteen minor findings, and no blocker. This release fixes the serious ones and the minor ones that were plain falsehoods on a public page. A refute pass over this release's own first draft found a blocker and six serious problems in the fixes, among them a phone line that would have pushed people to put their OS on GitHub when a local option exists. All are fixed here. The minor ones that are consistency or wording, not falsehood, are logged for the 2.0 work.

The 1.55.1 pack said one skill claims to work on a free plan. The real count is wider: the verify skill's report, the README's LinkedIn line, the model-routing page and a dozen skill descriptions. The README line is fixed here. The rest depends on a decision about what the free plan can run, which 2.0 makes.

## Integration protocol

1. Run the update. Files you never edited are refreshed. A changed file you did edit is shown as a diff, one at a time. The ones you are most likely to have edited are `rules/security-baseline.md` and `rules/entry-conventions.md`. The last one only swaps an example, so it's safe to accept. The `CLAUDE.md` changes matter most on GitHub and before setup: after setup your `CLAUDE.md` comes from the bootloader template, which this release does not change.
2. Your own `cadence/first-30-days.md`, if setup wrote one, still has the old promise, because an update never touches your own files. To change it, open it and replace "nothing leaves your machine without you, nothing is sent, nothing is published" with "the skills that write to people draft and stop, and the few that send act only when you ask."
3. On a ZIP install, type commands without the `/founder-os:` prefix: `/setup`, `/today`.
4. To update a curl or clone install, open the folder and say "update Founder OS". Don't re-run the installer.

## No Claude Code? The by-hand path

Nothing in this release changes how a script behaves. On a Mac, copy `Start Founder OS.command` from the 1.55.2 ZIP into your Founder OS folder for the new first-run note. The other edit worth making by hand is step 2 above, in your own `cadence/first-30-days.md`. Everything else is wording you can read on the GitHub page.
