# v1.54.2 - no command tells you to reinstall any more

Two of the last three releases fixed a message that told a correctly-installed founder to reinstall, or named a command that only exists on some installs. Both times the fix landed in the one file where the problem had been spotted. This release does what should have happened the first time: it sweeps the whole set.

## What changed

- **Twenty-two commands stopped telling you to reinstall.** If a command could not find its own instructions, it said "re-install the plugin". That advice is wrong on every install path: if you downloaded the ZIP or cloned the repo there is no plugin to reinstall, and on the path it fails hardest - a correct plugin install - the files are already sitting on your machine. Every one of those messages now says what actually helps: restart Claude Code, which reloads what is installed, and if it happens again, say "update Founder OS".

- **Commands stopped naming a command you might not have.** Messages said "Run /founder-os:setup first". That form exists on plugin installs; ZIP and clone installs register the short form instead, so the instruction was a dead end for the reader. They now say what to say: "set up Founder OS", "update Founder OS", "set up legal". Plain words work on every path.

- **The health check can find its own instructions on a plugin install.** `verify` looked for its instructions in the folder you happened to be standing in, which on a plugin install is your own folder. It was the same defect fixed for setup two releases ago, still standing in a second place. It now looks where the engine actually is first.

- **The docs say what the last two releases actually did.** The skill index still described v1.53.0 as the newest release. The health-check entry did not mention that its file checks are now a script's proof rather than an impression. The `where` entry did not say what "backed up" now has to earn. The security page did not carry the hard-link refusal added in v1.54.1. All four now match the code.

## Why it matters to you

**If a command ever failed and told you to reinstall:** it was almost certainly lying, and reinstalling would not have helped. Restarting Claude Code is the fix that works.

**If you installed from the ZIP or a clone:** the commands quoted at you now exist on your install. Before this, some of them did not.

**If nothing ever broke for you:** nothing changes. This release only alters what the OS says when something has already gone wrong, which is exactly when wrong advice costs the most.

## Integration protocol

1. The command and doc files arrive with the update itself. No action needed.
2. No script changed in this release, so there is nothing to copy by hand.
3. Nothing in your own files is touched and no behaviour changes except what the OS says when a command cannot find something.

## No Claude Code? The by-hand path

Nothing to do, and that is the honest answer. This release changes only the words the OS uses when something has gone wrong. The one thing worth carrying away is the rule behind it: when a tool tells you to reinstall, check whether it can actually see its own files first. Reinstalling to fix a lookup problem replaces working files with identical working files and loses you an afternoon.
