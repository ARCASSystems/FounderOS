# v1.52.0 - the brain feeds the team

Your seats have a read-list. Until now it never changed. The `inputs:` line on a registry row was written once, at hire, and a seat you dispatched on its fiftieth run knew exactly what it knew on its first - while three months of notes from books, calls and articles sat one folder away, read by nobody on the chart. Two stores in the same brain, learning nothing from each other. This release connects them, with one optional field and your yes.

## What changed

- **A knowledge note can now name the seats that should read it.** Add `seats: next-move-caller` to any file in `brain/knowledge/`, run `python scripts/agents_sync.py apply`, and that seat's agent file gains a `## Knowledge routed to you` section listing the note by id, topic and path. Comma-separate for more than one seat. That is the whole mechanism.

- **Pointers, never bodies.** The seat is told a note exists and where to find it. It opens the file itself when it runs. Nothing from your notes is copied into an instruction sheet, which keeps the knowledge layer's standing rule intact and stops a long note quietly becoming a long prompt. A seat is capped at 20 pointers, most recently captured first, with a line saying how many more are tagged to it - a truncation that does not announce itself reads as "that is all of them".

- **`seats: none` is a real answer, and it is the piece that makes this bearable.** The field has three states, not two: absent means never reviewed, a list of ids means routed, and `none` means reviewed and deliberately routed to nobody. When you decline, that decline is written down. Without it, every note you said no to comes back tomorrow morning and the morning after - and by the third one you have learned to ignore the question. A decline should cost one answer, not one answer per day forever.

- **Two places propose, and neither one tags anything by itself.** When `knowledge-capture` writes a note it compares the subject against your registry rows and asks at most one line: "this reads like it belongs to the account manager - route it there?" No obvious match means no question at all. Separately, `morning-loop` may raise one untagged note per run, ranked last behind everything that moves real business state, only when a slot is free, and never in the first week of a fresh install. Yes writes the ids, no writes `none`, and either way the question is closed for good.

- **Nothing about file ownership changed, on purpose.** The fold happens inside the same render that already produces your agent files, so v1.50.1's digest does all the work: tagging a note makes the seat show as `[stale]`, `apply` converges it, and a seat file you edited by hand stays `[modified]` and is never overwritten. A tag naming a seat that is no longer on your chart renders nothing, is reported by `check` as a dangling tag, and is never auto-cleaned - a retired seat's notes stay tagged in case the seat comes back.

## Why it matters to you

**If you have hired a seat:** it now starts each run knowing what you have learned that bears on its job, instead of re-reading the same five files forever. The read-list is the difference between an assistant and a colleague, and this is the first release where that list can grow.

**If you have not hired anything yet:** nothing happens, and that is the design. An install with no tagged notes renders byte-identical agent files to the ones v1.51.0 rendered - same bytes, no new section, no drift, no prompt. The field is optional and the questions only fire where a seat and a note plainly meet. You lose nothing by ignoring this release entirely.

**If you are wary of an OS that keeps asking things:** this is the release that takes the failure seriously. A repeated question is not a small annoyance, it is the thing that makes you stop trusting every question, including the ones that mattered. The tombstone exists so a "no" is permanent.

## Integration protocol

1. **Copy `templates/scripts/agents_sync.py` over your `scripts/agents_sync.py`.** It is generated code with no personalization in it, so a straight overwrite is safe.
2. **Copy the doctrine and the knowledge README** (`templates/rules/digital-employees.md`, `templates/brain/knowledge/README.md`) if you have not edited your copies. If you have, read the new sections and fold in what you want by hand - your edits are yours.
3. **If your `roles/employees.yaml` still carries the shipped `daily-assistant` row**, add `Bash(python scripts/agents_sync.py:*)` to its `tools` field. That is what lets the morning loop write a routing answer. `python scripts/employee_verdict.py charters` tells you if the row and the skill disagree.
4. **Run `python scripts/agents_sync.py check`.** With nothing tagged it reports exactly what it reported before. That is the upgrade proving it changed nothing you did not ask for.
5. **Then tag one note.** Pick the single note you would most want a seat to have read, add `seats: <that seat>`, run `apply`, and open the agent file. Start there rather than with a tagging sweep - the field is worth having only where it is true.

## No Claude Code? The by-hand path

**Write the pointer, not the note.** At the bottom of each team member's brief - a real one or a chatbot's standing instructions - keep a short list of the notes they should have read: title and where it lives, nothing more. Five lines, not five pages. Then keep the discipline this release is really about: when you decide a note is not for them, write that decision down beside the note. One line, "not for anyone". The value here is not the automation, it is that a review you already did never has to be done again - and that works in a paper notebook.
