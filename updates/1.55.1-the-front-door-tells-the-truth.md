# v1.55.1 - the front door tells the truth

An audit of the live product found front-page sentences that were true when written and aren't true now. Claude Code changed its default permission mode. The download link sent people to a page that installs nothing. Cowork moves its new tasks to the cloud on 6 October.

The install check also ended a narrow check with a wide claim. This release adds no feature. It makes what the product says match what it does.

## What changed

- **The send-gate wording.** The README said anything outside a role's grant "lands in your normal permission prompts". Claude Code in the terminal now starts in auto mode, where a reviewer model blocks risky actions instead of asking you, so that promise no longer held.

  The skills are still written to draft and stop, and for the five starter roles that rule is audited. But many skills, the email and proposal drafters among them, pre-approve shell commands, so no permission mode reliably stops a send today. The README now names that gap and says a hard send gate is coming in 2.0. `docs/first-day.md`, `rules/digital-employees.md` and the starter registry now say what happens outside a role's grant in each permission mode.

- **The download path.** The README and both start files sent people to `claude.ai/code`, which is Claude Code on the web and installs nothing. The README also called Claude Code free.

  Both start files now open `claude.com/download`, say a paid Claude plan is needed, and name the desktop app's Code tab as the no-terminal route: Local, then Select folder. They still need the Claude Code terminal tool to open the folder themselves, and now they say so.

- **Plugin updates.** The README said the plugin auto-updates. Claude Code leaves auto-update off for third-party marketplaces, this one included, so the docs now say how to update by hand and how to turn auto-update on.

- **Cowork and the cloud.** From 6 October 2026, new Cowork tasks on Pro and Max plans run in Anthropic's cloud. Anthropic's own help pages disagree on whether a scheduled task can use a folder on your computer. The docs had pointed Cowork timed jobs at your OS folder and called every cloud surface read-only.

  The README, the install guide, the tools guide, `CLAUDE.md`, `llms.txt` and the `routines` skill now describe each surface as Anthropic documents it today, and mark what we haven't tested as untested.

- **The global template.** The template for your global `~/.claude/CLAUDE.md` carried the maintainer's own working rules: a model-routing section, "always ask clarifying questions", and a developer's "typecheck, build, test". The routing section is gone.

  The questions rule now reads: act on the low-risk path and say what you assumed, state the approach in one line before an ambiguous build, and ask one sharp question only when being wrong is expensive. "Typecheck, build, test" became "check the work before calling it done". Whether setup should write that global file at all is a decision for 2.0.

- **The install check says what it checked.** `scripts/verify.py` used to end with "All present", which reads as a clean bill even when a skill has been deleted. Every result now ends with a "Checked:" line and a "Not checked:" line, worked out from what that run could actually compare.

  On a ZIP, clone or curl install it also printed a pass for "the version that shipped" without comparing anything. It now compares your `scripts/` with the shipped copy in `templates/scripts/`, so a hand-edited or half-updated helper shows up by name.

- **The pack rule has a test.** Every pack from 1.55.0 on must carry the five sections listed in `updates/README.md`, and a test in the maintainer's suite now fails before release when one is missing.

- **Two fixes from a whole-repo hygiene check.** Four shell scripts gain the exec bit, so `./scripts/install-git-hooks.sh`, which the README tells you to run, works on a Mac or Linux clone instead of saying "Permission denied". And one value in the UAE legal sources file is now quoted, so the file parses as YAML.

## Why it matters to you

If you run Claude Code in the terminal with its default settings, you're in auto mode. The skills still draft and don't send, but nothing in this version stops a send by itself. Many skills pre-approve shell commands, so even Manual mode doesn't ask before those run. Until the 2.0 send gate lands, read a draft before you ask for it to go out.

If you're installing for the first time and don't use a terminal, get the Claude desktop app, open its Code tab, choose Local, click Select folder, and pick the Founder OS folder. That route follows Anthropic's docs. We haven't yet watched a fresh install run it, and the pages say so.

If you installed with the plugin, updates don't arrive by themselves unless you turned auto-update on. Open `/plugin`, go to the Marketplaces tab, and choose Enable auto-update.

If you run a Cowork scheduled task that reads or writes your OS folder, check it after 6 October. Anthropic's pages disagree on whether it keeps working, so a timed job on your OS folder is safer in Claude Code.

If setup wrote your global `~/.claude/CLAUDE.md`, the copy on your machine still has the old rules. This update doesn't touch it, because it sits outside your Founder OS folder. Step 4 of the integration protocol below is the edit.

If none of this touches you, nothing in your own files changes.

## What the release gate found before this shipped

A context that built none of this read the diff and this pack and tried to break every claim, then went over the fixes a second time. The first pass returned sixteen findings: one blocker, eight serious, seven minor. Thirteen are fixed. Three are not, and each is logged for 2.0.

The blocker was in the fix itself. The first draft told you to switch to Manual mode to approve every action. That is false while a skill that pre-approves shell commands is running, and the email and proposal drafters are two of them. The advice is gone, and the gap is named instead.

The serious ones: the install check claimed a comparison that a ZIP or clone install skipped, the Cowork lines picked one side of two Anthropic pages that disagree, the desktop route was missing its untested label in several places, the pack said a test fails the build when the test lives in the maintainer's suite, and smaller overclaims and contradictions between pages. The second pass found the install check still printed a pass for the comparison it skipped, so it now runs that comparison.

The three not fixed: an update still does not refresh the two start files or `llms.txt`, so step 2 below says how to copy them. The folder's operating rules still carry the same model-routing note the global template lost. And some pages still name plans loosely: "Pro/Max" in places, no mention of the Console and cloud-provider routes Anthropic also allows, and one skill that says it works on a free plan. What the free plan can run is a decision for 2.0.

## Integration protocol

1. Run the update. Files you never edited are refreshed. A changed file you did edit is shown as a diff, one at a time, for you to accept or decline. The two you are most likely to have edited are `CLAUDE.md` and `rules/digital-employees.md`. Nothing in your own folders is touched.
2. **The two start files and `llms.txt` are not refreshed by an update yet, on any install path.** To get the new message for a machine without Claude Code, copy `Start Founder OS.bat` and `Start Founder OS.command` from the 1.55.1 ZIP into your Founder OS folder. If Claude Code already opens when you double-click, you can skip this.
3. Until the 2.0 send gate lands, read a draft before you ask for it to go out. No permission mode stops a send that a skill has pre-approved.
4. **Only if setup wrote your global `~/.claude/CLAUDE.md`.** Open it. Delete the section headed "Model Routing". Replace the line that starts "Always ask clarifying questions" with: "Act on the low-risk path and say what you assumed. Before an ambiguous build, state the approach in one line. Ask one sharp question only when being wrong is expensive." Replace "Typecheck, build, test." with "Check the work before calling it done."
5. Run `python scripts/verify.py` once. The last two lines should start "Checked:" and "Not checked:". If they do not, the new script did not land and the update should be run again. If it now names a script that does not match the shipped version, that is real and new: an earlier by-hand copy updated `scripts/` without `templates/scripts/`, or a helper was edited. Running the update fixes both.

## No Claude Code? The by-hand path

From the 1.55.1 release ZIP, copy `scripts/verify.py` over your own and `templates/scripts/verify.py` over its twin, so the check compares like with like, and copy both `Start Founder OS` files into your Founder OS folder. The rest is wording, which you can read on the GitHub page. If setup wrote your global `~/.claude/CLAUDE.md`, make the edit in step 4 above.
