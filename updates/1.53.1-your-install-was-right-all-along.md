# v1.53.1 - your install was right all along

A founder who installed the plugin exactly as documented said "set up Founder OS" and was told to reinstall the plugin. A founder on the ZIP path, the one advertised as needing no git, tried to connect Telegram and was refused with a reason that was not true. A third, whose install was missing one bookkeeping file, was told to create it by hand and try again.

In all three cases the install was correct and the OS handed its own confusion back as homework. An outside review of v1.53.0 caught the pattern; this release closes it. One more fix rides along from the same review: the version-history skill used to suggest adding your own name to the privacy guard, which made the very first save fail right after you said yes to a privacy feature.

## What changed

- **Setup finds its own instructions on a plugin install.** The setup command used to look for its wizard in the folder you opened, which on a plugin install is your own folder - empty on purpose, because the engine lives where Claude Code keeps plugins. It now looks where the engine actually is first, then falls back. And if it genuinely cannot find the wizard, it says so and suggests a restart instead of telling you to reinstall something you installed correctly.

- **Connectors work with no git installed.** Storing a key requires proof the file it lands in can never be committed. The old proof asked git, and on a machine with no git the failed question was read as "not protected", so every connector was refused - with a message blaming a file that was configured correctly all along. Now, where version history exists, git still answers; where it does not, the OS reads the shipped ignore list directly. Telegram, Gemini, and ElevenLabs connect on a fresh ZIP install. The same pass also made the writer stricter: a target carrying a folder path is refused outright instead of quietly landing somewhere you did not name, and a newly created `.env` is created readable by your user only where the platform supports it.

- **A missing version marker routes to repair, not to you.** If the file recording your install's version is missing, "update Founder OS" now says it cannot tell what you have, refreshes the engine to the current release, and restores the marker - skipping only the guided what-changed walkthrough, since there is no known starting point to walk from. It never again asks you to author a file.

- **The privacy guard no longer suggests blocking your own name.** Your name lives in your identity file by design, so blocking it made every save that touches your identity fail. The guard is now offered for what it is for: names that must never enter your files at all, such as a client under NDA. Most people rightly skip it.

- **The docs stopped promising hooks the plugin does not register.** The plugin carries the slash commands; hooks are wired by setup into the OS folder it builds, and fire when you open Claude Code there. That was always the behaviour. The install guide now says so in plain terms instead of claiming hooks register automatically across every project.

- **The curl installer prints the right command.** It said `/founder-os:setup`; on that path commands are bare, so the right command is `/setup`. Two related claims in the install guide were corrected to match what the installer actually does when piped from curl.

## Why it matters to you

**If you installed via the plugin marketplace:** setup now works first try. The old failure hit exactly the person who followed the instructions.

**If you run a ZIP install with no git:** connectors were dead on your path and the refusal blamed your setup. They work now, and nothing about your install needed fixing then either.

**If you added your own name to the privacy patterns after an earlier version suggested it:** remove that line. It blocks every save that touches your identity file.

**If none of these ever bit you:** nothing you use day to day changes. The behaviour was only wrong at the exact moments it mattered most - first setup, first connector, first repair.

## Integration protocol

1. **Copy `templates/scripts/connect.py` over your `scripts/connect.py`.** No personalization in it; a straight copy is correct.
2. **Open `scripts/private-name-patterns.txt` if you ever filled it in.** If your own name is on a line, remove that line. Client names under NDA stay.
3. The command, skill, and doc files in the table arrive with the update itself. No action needed.
4. Nothing else in your install changes and no behaviour anywhere else is affected.

## No Claude Code? The by-hand path

Two edits, both one minute. Copy `templates/scripts/connect.py` over `scripts/connect.py` - that is the whole connector fix. Then open `scripts/private-name-patterns.txt` and make sure your own name is not in it; if it is, delete that line. Everything else in this release is wording and routing inside files the update replaces wholesale, so there is nothing further to do by hand.
