# v1.44.0 - what this is, written down

Copy only. No machinery, nothing to run, nothing to keep current.

## What changed

A question kept coming back and the product never answered it in writing: how is this different from someone who uses Claude or ChatGPT well? The architecture had an answer the whole time and never said it out loud, which meant every person who asked got a different improvised version.

It is now written in `README.md` and `docs/first-day.md`, as four things that do not come from prompting better:

- **The context is a folder you own.** Plain markdown on your disk. Point a better model at it next year and nothing is lost. Open a file and you can see exactly what it thinks it knows about you.
- **Nothing becomes a fact because it was said once.** A name from a call, a number in a transcript. Those stay provisional until you confirm or cut them, so the OS does not end up telling you your own work slightly wrong, with total confidence, in front of somebody.
- **Five named roles, each one graded.** Not one assistant that is good at everything and accountable for nothing.
- **A gate between a draft and a send.** Written into each role's permission grant rather than asked for politely in a prompt, so it holds on a bad day.

Plus one framing that had been implied and never stated: this is for founders **and** for people running teams, including the employee a single workstream lands on. When a team runs it, each person runs their own, and what passes between them is shared work items. What never passes, in either direction: pay and commercial terms, one person's private profile landing in someone else's system, and personal data about anybody. Several people inside one live session is not something this does today, and the docs now say so plainly rather than leaving it ambiguous.

Four structural writing tells also landed in `rules/writing-style.md`. The banned-word list catches vocabulary; these four survive a find-and-replace, which is what makes them the ones left in current AI writing once the words are clean: an aphorism budget of one per document, no label-colon paragraph openers, no defining a thing by what it is not, and a docstring that is a contract rather than a case study.

Two doctrine paragraphs landed in `rules/os-as-harness.md`: a checker that reports findings which are not real teaches you to skim past the true ones, so a red checker is a bug in the checker until proven otherwise. And any count shown in a daily surface names the file it came from, because a wrong number looks exactly like a right one and drifts silently until somebody reconciles it by hand.

## Why it matters to you

**If you are deciding whether to install:** read the README section first. If those four things are not worth a folder on your disk, this is not for you and that is a fine outcome.

**If you already run it and someone asks you what it is:** the README section is the answer, and it is shorter than the one you have been improvising.

**If you write with the OS:** the four structural tells are the ones worth learning. Everything else in the writing rules is a word list you can look up.

**You can skip this pack entirely.** Nothing in it changes behavior. It is what to say when someone asks.

## Integration protocol

1. **Take `rules/writing-style.md` if you have not edited yours.** If you have, the update proposes one added section around your edits. Read that diff on its own.
2. **Take `rules/os-as-harness.md`.** Nothing personalized lives in it.
3. **Read the README section once.** That is the whole protocol for the rest of this pack.
4. **Nothing to run.** There is no command here and no state to refresh.

## No Claude Code? The by-hand path

**Copy one file: `rules/writing-style.md`.**

It is the one that pays with no tooling, because it is a checklist you can apply to anything you write in any tool. Read the Structural Tells section last and apply it after the word list, which is the order it is written in.

If you want a second, the four-point answer in the README is worth having in your own words before the next time somebody asks you what you are running.
