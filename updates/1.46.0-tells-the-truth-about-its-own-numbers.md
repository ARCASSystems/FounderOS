# v1.46.0 - the OS tells the truth about the numbers it produces

The OS already kept capture honest: a name or an amount heard once is held as unconfirmed until you confirm or cut it. That covered what comes in.

This release covers what goes out. When the OS sizes a market, prices a proposal, or reads a competitor, it produces numbers, and those numbers get pasted into decks and shown to buyers and investors. An AI-drafted research document invents precise-looking claims, and a precise-looking claim is the one that survives review, because it reads as though somebody already checked it.

A verification pass over a real seven-document research pack found about 40 suspect claims in four repeating classes: unsourced precise statistics, verbatim quotes with no retrievable source, universal negatives nobody can verify, and one cost row off by 11 percent in a table whose other nine rows were right. That last one is the class that hides best.

## What changed

- **Three claim tiers, and a script that reads your document back.** `rules/research-integrity.md` defines them: `[MEASURED]` names the artifact and the command that re-derives the number, `[SOURCED]` carries one live URL and the date you fetched it, `[ESTIMATE]` states the assumption inline so a reader can swap it. `scripts/claims_check.py` scans a finished document for untagged numbers, quotes with no source, unbounded universal negatives, and arithmetic that does not reconcile. Standard library only. It warns, it never blocks, and it never edits your file.
- **Two hard rules.** A verbatim quote attributed to a person carries a retrievable link and date or it comes out. A universal negative ("no tool does this") gets rewritten as the bounded search you actually ran: "checked A, B and C on this date, found none." That version is true, defensible, and still makes the point.
- **Wired where numbers are produced.** `strategic-analysis`, `unit-economics` and `proposal-writer` name the rule in their bodies. `ship-deliverable` gained Link 3.5, which runs the check on research-class deliverables before anything leaves your machine. The reviewer is not the writer: it runs as a second pass over the finished document, never while drafting.
- **A new skill: `self-diligence`.** Say "what would an investor ask me about this business" and it scores five dimensions against evidence in your own files, then lists the questions a diligence analyst would ask. Anything your files cannot ground becomes a question to you. It is never invented and never softened into a hedge, because an analyst who fills in the missing half from general knowledge hides exactly where the risk is.
- **Entity folders, so an identity thickens instead of sprawling.** A person, venture or topic starts as one file in `context/entities/`. When it outgrows that (size, touch frequency, or you say so), `scripts/entity_check.py` proposes promotion to a folder with a fixed shape: `profile.md` for the current read, `log.md` append-only for the evidence, `sources/` for their documents as sent. You approve the promotion. It never happens on its own.
- **Identity review, so a profile never quietly fossilises.** Entities carry a `reviewed:` date. The weekly review surfaces any that are 60+ days stale AND have real touches since - you kept working with them while the written read of them was never confirmed. Confirm, correct, or archive. An entity that simply went quiet is not surfaced, because dormancy is not debt.
- **The gap question.** When you describe how something should work and the log shows it running differently, the morning loop asks about the gap instead of picking a side. Designed intent, enacted practice, and the question. Your answer lands in the profile. Nobody writes down why a stated process and a real one diverge unless something asks.
- **The ownership line, said plainly.** Every other tool in this category asks you to make how you work legible to their platform. This is files on your machine you can read, edit, fork, and keep the day the vendor disappears. The README says it, and it also says the thing that is not true of us: this runs when you open it and when a hook fires, not all day on its own.
- **A first-session prompt card and a scenarios page.** Nine sentences to type after setup, in the README. `docs/a-day-in-the-os.md` walks nine real situations end to end, with outcomes stated at the size they actually are. There is not a single percentage or multiplier on that page, deliberately: it is exactly where invented numbers go.

## Why it matters to you

**If you send anyone a document with numbers in it:** run `python scripts/claims_check.py <file>` before you send it. The four or five claims it surfaces are the ones that would have been challenged in the room, and you find them while you can still fix them.

**If you are raising, selling, or partnering:** run `/founder-os:self-diligence` before the meeting, not after. The list of questions you cannot yet answer is the point of the output.

**If you keep coming back to the same people:** entity folders stop the current read of someone from being buried under two years of notes, and the review stops a profile you wrote in February from being read in August as if you still stood behind it.

## Integration protocol

1. **Take the system-layer files.** All of it is engine and docs. Nothing writes into your data folders, and nothing changes a file you have personalized.
2. **Create the directory if you want entities:** `context/entities/`, with the README from `templates/context/entities/README.md`. Skip it and everything else in this release still works; `entity_check.py` reports "nothing to scan" and exits clean.
3. **Try it once on something real:** `python scripts/claims_check.py <any document you have sent recently>`. What it finds on a document you already shipped is the argument for running it before the next one.
4. **Nothing to migrate.** No file format changed, no existing convention moved.

## No Claude Code? The by-hand path

The whole of this release works without the model, because the useful half is two scripts and a habit.

**The scripts:** `python scripts/claims_check.py <file>` and `python scripts/entity_check.py` both run on plain Python 3 with no packages, no key, and no account. They read; they never write.

**The habit, which is the actual product:** before any number goes into a document someone will act on, write one of three things next to it. What file and command reproduce it. What link and date support it. Or what assumption produced it. Then quotes carry links, and "nobody does this" becomes "I checked these three on this date."

You can do that in any text editor, in any tool, today. The script only finds what you missed.
