# v1.54.1 - the backup line had to earn it

An outside review of v1.54.0 found three ways the OS could tell you your work was safe when it was not, and one way a connector could write a secret into a file you never named. The backup answer shipped one release earlier as the honest one. It was not honest enough.

## What changed

- **"Backed up" now means a copy exists somewhere that is not this computer.** Three separate things used to earn that line when they should not have. A folder holding a file version history is told to ignore reported as fully backed up, even though that file has no second copy anywhere - and the ignored file is the likeliest thing in any folder to be lost, precisely because nothing ever mentions it. A folder whose name or parent folder had an accent in it reported as backed up while today's unsaved edits sat on the laptop. And a second copy stored in another folder on the same disk counted as "away from this computer", which it plainly is not. All three now read correctly.

- **A folder that is only partly copied says so.** The line reads: an older version is saved, some of what is in this folder right now exists only on this computer. That covers a file you edited today, a file you never added, and a file that is ignored, because for the question "what would survive the laptop dying" those are the same fact.

- **Connectors refuse to write a secret into a file that is secretly two files.** A file can have a second name pointing at the exact same content elsewhere on the disk. Every safety check the connector ran passed, because by every path-based measure the target was inside your OS folder - and the secret landed in the other file too. It is now refused with the one thing you can do about it.

- **The install check catches an out-of-date file, not just a missing one.** A file left behind by an interrupted update is perfectly readable and quietly wrong, which is the shape of nearly every defect found in the last three releases. The check now compares what is in your folder against what actually shipped, and names anything that does not match.

- **Two ways the install check could pass while proving nothing are closed.** It could measure your install against a different plugin's files if that plugin happened to be installed, and it accepted a hook set up that merely mentioned the OS while running something else. Both now fail honestly instead of passing falsely.

- **The install check reads like a person wrote it.** It used to print its own internal labels. It now names what is being checked in plain words.

- **Setup can no longer be told it finished when it did not.** Re-running setup clears the old completion record first, an empty or truncated record counts as no record at all, and if setup is mid-run that always wins over a stale "finished" marker. Silently opening as though nothing happened is the failure these markers exist to prevent.

- **Update stopped naming a command that only exists on some installs.** Four messages told you to run a command that does not exist on the download or clone paths. They now say what to say instead.

## Why it matters to you

**If you keep real work in your OS folder:** run "where is my work" again after this update. Folders that said backed up may now say saved on this computer only, or partly copied. That is not the tool getting worse - the earlier answer was wrong, and this is the one you can act on.

**If you use a folder on the same machine as your backup:** the OS will now tell you plainly that it does not count. Whether that changes what you do is your call, but you should be making it with the true picture.

**If you have connected Telegram, Gemini, or ElevenLabs:** nothing to redo. The refusal only fires on an unusual file shape most people will never create.

**If you are mid-setup or have re-run setup:** the resume behaviour is stricter and more honest. Nothing to do.

## Integration protocol

1. **Copy `templates/scripts/where.py`, `templates/scripts/connect.py` and `templates/scripts/verify.py`** over their `scripts/` twins. Straight copies, no personalization in any of them.
2. **Run `python scripts/verify.py`.** It will now tell you if any other OS file in your folder is out of date, which is worth knowing once.
3. **Run "where is my work"** and read the backup lines again with fresh eyes. Some will have changed. The new ones are the true ones.
4. Nothing else in your install changes and no behaviour anywhere else is affected.

## No Claude Code? The by-hand path

Copy the three scripts named in step 1, then run `python scripts/where.py --all` and read the bottom block. The question it answers is the only one that matters here: if this laptop died tonight, what would be gone? A folder that says it exists only on this computer needs a copy somewhere else today - a synced folder or a zip on a drive is enough. The reason this release exists is that the OS used to answer that question wrongly in three different ways, and a wrong reassurance is worse than no answer, because you stop checking.
